Binding location lookups

Compare the queries at 8907303 with 73e2aea (v0.12.0). Both stores use their complete storage migration and initialization SQL. Everything is synthetic and runs in memory. This file contains SQLite WASM and all SQL: double-click it, with no server or network.

Each pending identity adds two bindings: a tombstone with a settled base in c0 and a pending create in c1. Unrelated identities share the same source and alternate between present and absent bases. Time is the median of 31 warm executions of one lookup, excluding prepare and bind. VM steps and full-scan steps are SQLite statement counters, not estimates. “Pending batch” runs one lookup for every pending identity; it measures the lookup loop, not the complete Rust placement read. Data creation is excluded. A zero time means the lookup fell below the browser's clock precision; use the VM-step counter to compare small costs.

Ready. SQLite 3.54.1, matching the crate's bundled SQLite version.
